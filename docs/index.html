まず全体像

Dart ってどんな言語？

細部に入る前に、これから何度も出会う「Dart らしさ」を7つだけ。あとで各設計の中で実物を見ます。

型があるが、推論もする

変数や引数に型を付ける静的型付け。でも明らかな場合は推論してくれるので冗長になりすぎない。型のおかげで「渡し間違い」がコンパイル時に分かる。

final n = 8; // int と推論

null 安全が標準

「null かもしれない」型は ? を付けた時だけ。付いていない型に null は入れられない。実行中の null クラッシュを、設計の段階で締め出す。

int? id; String name; // name は null 不可

「式」で書ける

switch や条件が値を返す式として書ける。分岐の結果をそのまま変数に入れられるので、短く・意図が直線的になる。

final c = switch(t){ ... };

非同期が言語に内蔵

Future（あとで届く1つの値）と Stream（流れ続ける値）が組み込み。async/await で「待つ」処理を普通の上から下のコードのように書ける。

final db = await open();

不変（イミュータブル）志向

final/const が手軽で、一度作った値を変えない設計をしやすい。変えたいときは「一部だけ差し替えた新品」を作る（copyWith）。バグの温床＝うっかり書き換えを減らす。

final p2 = p.copyWith(taxRate: 10);

名前付き引数で読める呼び出し

引数に名前を付けて渡せる（required で必須化）。UI のツリーや設定だらけの生成が、何を指定しているか一目で分かる。

Product(name: '弁当', taxRate: 8)

複数の値をまとめて返せる

レコード（軽量なタプル）で、関数から複数の値を一度に返せる。受け取る側は分割代入でさっと展開。小さな「2つ組」をわざわざクラスにしなくてよい。

final (a, b) = loadDraft();

  1. 設計のねらい … その部品が何を担うか（なぜ要るか）。
  2. 自然言語のアルゴリズム（左）… 日本語の手順。プログラムを知らなくても追える。
  3. Dart 実装（右）… 実際のコード。①②③ の付いたハイライトが、注目の言語機能。
  4. ここで分かる Dart の特徴 … ①②③ に対応する解説。コードのその場所と結びつけて読む。
01

データの形 — 商品・明細・値引き

アプリの土台は「データの形」。商品とは何を持つのか、カートの1行とは何かを、変わらない（不変な）型として定義する。

lib/domain/

自然言語のアルゴリズム

  1. 商品は 名前・税抜価格・税率(8か10)・カテゴリを持つ。保存前は ID がまだ無い。
  2. 一度作った商品は勝手に書き換えない。直したいときは別の新品を作る。
  3. 値引きは「金額引き」か「率引き」のどちらか＋数値。
  4. カートの1行は 商品＋数量＋（あれば）単品値引き。値引きは「無し」もありうる。

「無し」を許すかどうかを型で表すのがポイント。null を入れてよい所と、絶対入れない所を分ける。

Dart 実装

enum1 DiscountType { amount, percent }   // 値引きの種類は2つだけ

class Discount {
  final2 DiscountType type;
  final int value;
  const2 Discount(this.type, this.value);
}

class Product {
  final int?3 id;        // 未保存なら null（だから ? 付き）
  final String name;        // ? 無し → null は入らない
  final int unitPriceExclTax;
  final int taxRate;        // 8 か 10
  final String category;
  const Product({
    this.id,
    required4 this.name,
    required this.unitPriceExclTax,
    required this.taxRate,
    required this.category,
  });
}

ここで分かる Dart の特徴

1
列挙型enum

「取りうる値が決まっている」ものを型にする。amount/percent 以外は存在しえないので、打ち間違いや想定外の値が入らない。

2
不変final / const

final は一度だけ代入＝後から書き換えない。const はコンパイル時に確定する定数オブジェクト。変わらないと決めるとバグが激減する。

3
null 安全int?

? が付いた型だけ null を許す。id は「まだ無い」がありうるので int?、name は必ずある値なので String。型で意図を語る。

4
名前付き＋必須{required}

{} で囲むと名前付き引数。required で「省略不可」に。生成側が Product(name: …, taxRate: …) と読めるようになる。

02

単品値引き — 1行ぶんの計算

明細1行の税抜額に値引きを適用する、純粋な計算。お金なので小数を使わず整数の円で、端数は切り捨てる。

register_calc.dart

自然言語のアルゴリズム

  1. 値引きが無ければ、そのままの金額を返す。
  2. 金額引きなら、その額を引く。
  3. 率引きなら「価格 × 率 ÷ 100」を計算し、1円未満は切り捨てて引く。
  4. 引きすぎてマイナスになったら 0 にする。

「÷して切り捨て」を1つの演算でやれるのが効くところ。

Dart 実装

int applyLineDiscount(int lineExcl, Discount? d) {
  if (d == null) return lineExcl;1

  final cut = switch2 (d.type) {
    DiscountType.amount  => d.value,
    DiscountType.percent => lineExcl * d.value ~/3 100,
  };

  final result = lineExcl - cut;
  return result < 0 ? 0 : result4;
}

ここで分かる Dart の特徴

1
null ガード

引数 Discount? d は null かもしれない。先頭で d == null を弾くと、以降の d.value は安全に使える（コンパイラも「ここから先 d は非null」と理解する）。

2
switch 式=>

分岐の結果をそのまま値として返す。final cut = switch(...) のように代入できる。enum を相手にすると「全パターン書いたか」もチェックされる。

3
整数除算~/

/ は小数を返すが ~/ は商を整数で返す（＝切り捨て）。お金の計算で誤差を出さない要。1000 * 33 ~/ 100 = 330。

4
三項演算子

条件 ? A : B も式。「0未満なら0、でなければそのまま」を1行で。Dart は式で書ける場面が多く、短く読み下せる。

03

全体値引きの按分 — 端数をどう配るか

「合計から○○円引き」を、8% と 10% のグループに小計の比で割り振る。整数で割ると1〜数円あまるので、合計が狂わないよう寄せる。

register_calc.dart

自然言語のアルゴリズム

  1. 全グループの小計を合算する。
  2. 値引きが0か小計が0なら、全グループ0で終わり。
  3. 各グループに「値引き × そのグループ小計 ÷ 合計」を配る（切り捨て）。
  4. 切り捨てた分、配った合計が値引き額に少し届かない。そのあまりを、小計が最大のグループに足す。

「合計＝値引き額」を必ず守るための後始末がポイント。

Dart 実装

Map<int, int>1 distributeOrderDiscount(
    Map<int, int> subtotals, int amount) {

  final total = subtotals.values.fold2(0, (a, b) => a + b);
  if (amount <= 0 || total <= 0) {
    return { for (final r in subtotals.keys) r: 0 }3;
  }

  final alloc = <int, int>{};
  var allocated = 0;
  for (final e in subtotals.entries) {
    final d = amount * e.value ~/ total;   // 比例配分（切り捨て）
    alloc[e.key] = d;
    allocated += d;
  }

  final remainder = amount - allocated;    // あまり
  if (remainder != 0) {
    final maxRate = subtotals.entries
        .reduce4((a, b) => a.value >= b.value ? a : b).key;
    alloc[maxRate] = alloc[maxRate]!5 + remainder;
  }
  return alloc;
}

ここで分かる Dart の特徴

1
ジェネリクスMap<int,int>

「税率→値引き額」のような型のはっきりした連想配列。<鍵の型, 値の型> を指定するので、取り違えをコンパイラが防ぐ。

2
畳み込みfold

コレクションを1つの値に「畳む」高階関数。fold(0, (a,b)=>a+b) は合計。ループを書かず、意図（合計したい）を直接表す。

3
コレクション for

マップ/リストのリテラルの中に for を書ける。{ for (r in keys) r: 0 } で「全キーを0で初期化したマップ」を一息で作る。

4
reduce

要素同士を比べて1つに絞り込む。ここでは「小計が最大のエントリ」を選ぶ。fold と違い初期値なしで先頭から畳む。

5
非null表明!

alloc[maxRate] はマップ参照なので int?（無いと null）。直前で必ず入れたと分かっているので ! で「null じゃない」と断言する。乱用は禁物だが、根拠があるときの脱出弁。

04

会計の組み立て — computeReceipt

明細・全体値引き・預かり金を受け取り、税率別の集計とお釣りまで揃ったレシート（結果のかたまり）を返す。状態を持たない純粋関数。

register_calc.dart

自然言語のアルゴリズム

  1. 各明細に単品値引きを適用し、税率ごとに小計を足し込む。
  2. 全体値引きを計算し、税率グループへ按分（03の関数を呼ぶ）。
  3. 税率の小さい順に並べ、各グループの税額を切り捨てで出す。
  4. 課税ベースと税額を積んで合計、預かりからお釣りを出し、まとめて返す。

入力から出力を組み立てるだけで、外を書き換えない＝何度呼んでも同じ。

Dart 実装（要点を抜粋）

ここで分かる Dart の特徴

1
名前付き引数の関数

引数が増えても呼び出しが computeReceipt(lines: …, tendered: …) と読める。順番を覚えなくてよく、取り違えが起きにくい。

2
Map.updateifAbsent

「キーがあれば更新、無ければ初期化」を1つで。ifAbsent に初回の値を渡す。税率ごとの小計を、存在チェックを書かずに足し込める。

3
カスケード..

list..sort() は「その list に対して sort して、list 自身を返す」。一時変数を作らず、生成→設定を流れるように繋げられる。

4
純粋関数＝結果を返す設計

グローバルや画面を書き換えず、入力→新しい Receipt を返すだけ。だから単体テストが容易で、同じ入力なら必ず同じ結果（02〜04はテストで固めてある）。

05

司令塔 — RegisterModel（状態）

カートを覚え、操作のたびに「再計算 → 保存 → 画面へ通知」をまとめて行う。計算は04、保存はDB層に委ね、自分はつなぎ役に徹する。

lib/state/register_model.dart

自然言語のアルゴリズム

  1. 現在のカート明細を内部に持つ（外から直接いじらせない）。
  2. 「商品を足す」とき、同じ商品が既にあれば数量+1、無ければ新しい行を追加。
  3. 変更したら保存し（待つ）、画面に「変わったよ」と知らせる。

外部は read 専用ビューしか見られない。変更は必ずメソッド経由＝保存と通知が必ずセットで走る。

Dart 実装

class RegisterModel extends ChangeNotifier1 {
  final CartRepository cartRepo;
  List<CartLine> _lines2 = [];   // _ で始まる＝非公開

  List<CartLine> get2 lines => List.unmodifiable3(_lines);

  Future<void>4 addProduct(Product p) async4 {
    final idx = _lines.indexWhere((l) => l.product.id == p.id);
    if (idx >= 0) {
      _lines[idx] = _lines[idx].copyWith(quantity: _lines[idx].quantity + 1);
    } else {
      _lines.add(CartLine(product: p, quantity: 1));
    }
    await4 cartRepo.replaceLines(_lines);  // 保存（完了を待つ）
    notifyListeners()1;                 // 画面へ通知
  }
}

ここで分かる Dart の特徴

1
継承と通知ChangeNotifier

extends で既存のクラスを土台にする。ChangeNotifier は「変わったら購読者に知らせる」機能を提供し、notifyListeners() で画面の再描画を促す。

2
非公開_＋getterget

名前が _ で始まるとそのファイル外から見えない。中身 _lines は隠し、get lines で読み取りだけ公開する。

3
不変ビューList.unmodifiable

外へ渡すのは「書き換え不可のリスト」。受け取った側が勝手に add できないので、変更は必ずモデルのメソッド経由になる。

4
非同期Future / async / await

保存はあとで終わる処理＝Future。async 関数の中で await すると、完了を待ってから次行へ。コールバックの入れ子にならず上から下に読める。

06

カート復元 — 2つの値を返す

起動時、保存された「途中のカート」を読み戻す。明細リストと全体値引きの2つを一度に返したい。消えた商品の行はスキップ。

lib/data/cart_repository.dart

自然言語のアルゴリズム

  1. 保存済みの明細行を順に読む。
  2. その行の商品がもう存在しなければ飛ばす。
  3. 残った行から明細を組み立てる。
  4. 全体値引きも読み戻し、「明細リスト」と「値引き」をまとめて返す。

呼び出し側は2つを別々に受け取りたい → レコードと分割代入が活きる。

Dart 実装

ここで分かる Dart の特徴

1

複数の値の軽量な組。(List<CartLine>, Discount?) で「明細と値引きの2つ組」を返り値型にできる。2つのためだけにクラスを作らなくてよい。

条件に合わない行は continue でその回を飛ばす。p == null（=削除済み）なら何もしない、を素直に書ける。

4
分割代入

07

売上一覧 — 流れ続ける値（Stream）

売上テーブルが変わるたびに、最新の一覧を自動で流す。UI はそれを受けて勝手に描き直す。「取りに行く」のでなく「流れてくる」。

lib/data/sales_repository.dart

自然言語のアルゴリズム

  1. 売上を新しい順に、件数を絞って問い合わせる。
  2. その問い合わせ結果を購読する（変化があるたび届く）。
  3. 届いた行を、画面表示用の軽い形に変換して流す。

1回きりの値なら Future。何度も届くなら Stream。会計が増えるたび一覧を更新したいので Stream。

Dart 実装

    ..limit(limit);

  return query.watch()2            // DBの変化を Stream に
      .map3((rows) => rows

StreamBuilder<List<SaleListItem>>(stream: repo.watchRecent(), …)

ここで分かる Dart の特徴

1
StreamStream<T>

時間とともに何度も値が流れる通り道。Future（1回）と対になる概念。「最新の一覧」のように更新され続けるものに向く。

2
リアクティブな購読.watch()

drift は .get()（1回取得）に対し .watch() で変化を監視する Stream を返す。売上が増えれば自動で次の値が流れる。

3
宣言的変換.map

流れてくる行を、その都度 map で表示用の形へ変換。「どう変えるか」を書くだけで、いつ・何回かは Stream に任せる。UI 側は StreamBuilder が再描画してくれる。

08

起動 — main で土台を組む

アプリの入口。DBを開き、初回ならサンプル投入、カートを復元してから画面を立ち上げる。準備が終わるまで待ってから runApp。

lib/main.dart

自然言語のアルゴリズム

  1. 下準備の合図を出す（Flutter の初期化）。
  2. データベースを開く（完了を待つ）。
  3. 商品が空ならサンプルを入れる。
  4. 退避カートを復元する。
  5. 準備が全部終わってからアプリを起動。

「待つ」べき処理が並ぶので、入口の main 自体を非同期にする。

Dart 実装

ここで分かる Dart の特徴

1
非同期な入口main() async

プログラムの開始点 main も async にできる。だから起動処理の中で堂々と await できる。

2
トップレベル関数

Dart はクラスに属さない関数を直接置ける。main もそう。Java のように全部をクラスで包む必要がない。

3
await で順序保証

await openWebExecutor() はDBが開くまで待つ。次の行は「開いた後」に必ず実行される＝初期化の順番が崩れない。

4

「空のときだけ入れる」。2回起動しても二重投入されない。名前が意図（空なら）を語る — このノートが推す書き方。

5
runApp で起動

Flutter は runApp(ルートのウィジェット) で描画が始まる。すべての準備が済んでから呼ぶのがコツ（途中の空状態を見せない）。
